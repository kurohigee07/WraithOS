# AI usage disclosure

WraithOS is developed by a single maintainer with assistance from
conversational AI tools. This file documents the scope so reviewers
and contributors can assess the project accurately. It is separate
from `CONTRIBUTING.md`, which covers policy for external contributions.

## Where AI is used

- Patch and code drafting against a maintainer-written specification
  (boot chain, RAUC flow, dm-verity formula, security invariants).
- Debugging (error triage, hypothesis generation, shell command
  construction).
- Documentation drafting from maintainer-provided outlines and claims.
- English phrasing and translation for non-native English writing.

## Where AI is not used

- Architectural decisions, threat model, and security rationale.
  The security model and known-limitations list in `docs/security.md`
  were specified by the maintainer; prose was drafted with AI
  assistance and reviewed against the running system before commit.
- Accepting changes untested. Every commit is verified against a
  running QEMU ARM or x86 system (boot, wizard, RAUC install cycle,
  dm-verity check). Commits that fail functional test are rejected
  regardless of origin.

## Verification commitment

The maintainer runs every release artifact and reproduces the records
in `docs/testing.md` before tagging. Release binaries are built from
committed source, not generated by AI tooling.

## Policy reference

External contribution policy is in `CONTRIBUTING.md`. This file covers
the maintainer's own workflow and is reviewed with each release.
